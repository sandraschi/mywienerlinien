🔥 Hot-Reload Development Pattern

⚠️ The Problem: Traditional Docker development wastes 5 minutes on EVERY code change.

The Traditional (Broken) Workflow

# Change 3 lines of code
docker compose build  # ⏳ Wait 5 minutes
# Test, find bug
docker compose build  # ⏳ Wait 5 minutes AGAIN
# Repeat 20 times = 100 minutes wasted

The Solution: Volume Mounts + Hot-Reload

✅ Core Principle: Code lives on HOST, container reads via volume mount. 
services:
  app:
    build: ./app
    volumes:
      - ./app:/app  # 👈 Mount code directory
    command: uvicorn app:app --reload  # 👈 Hot-reload enabled

Result: Edit code → Save → See changes in 1 second ✅

Pattern 1: Hot-Reload in Docker

Best for: Full-stack development with multiple services

services:
  frontend:
    build:
      context: ./frontend
      target: dev
    volumes:
      - ./frontend:/app
      - /app/.venv  # Exclude venv
    command: uvicorn app:app --reload
    environment:
      - PYTHONUNBUFFERED=1
      - DEBUG=true

Pattern 2: Native Development

Best for: Fastest iteration, debugging

# Start database only
docker compose up -d db

# Run app natively
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

$env:DATABASE_URL = "postgresql://user:pass@localhost:5433/db"
uvicorn app:app --reload
💡 Benefits:
  • ⚡ Code changes in ~1 second
  • 🐳 Full Docker environment
  • 👥 Team consistency
  • 🔧 Only rebuild when dependencies change

🚨 The --no-cache Trap

🔴 CRITICAL: The most expensive Docker mistake that wastes HOURS

The Trap

# ❌ WRONG: Downloads entire internet (15+ minutes)
docker compose build --no-cache frontend

# ✅ RIGHT: Uses cached layers (30 seconds)
docker compose build frontend

# ✅ BEST: Hot-reload (1 second, no build!)
# Just save your .py file

When --no-cache is WRONG (99% of time)

  • ❌ Changed Python/Node/Go code files
  • ❌ Changed HTML/CSS/JS files
  • ❌ Changed config files (.env, .yaml, .json)
  • ❌ "Just to be safe" (not safer, just slower)
  • ❌ After git pull
  • ❌ "It failed once so now I always use it"

When --no-cache is Appropriate (1% of time)

  • ✅ requirements.txt changed AND regular build failed
  • ✅ Final production build before deployment
  • ✅ Suspected cache corruption (very rare)

Real Cost Analysis

Build Type Time What Happens
Regular Build 30 sec - 2 min Uses cached pip packages, only copies changed code
--no-cache Build 10-20 minutes Downloads 50+ packages, compiles everything from scratch
Waste Per Build 8-19 minutes Downloading packages you already have!
Over 20 rebuilds: 160-380 minutes wasted = 2.6-6.3 HOURS of your life gone!

Why People Fall Into This Trap

1. "My build failed once, so now I always use it"

Fix: Investigate why build failed, fix root cause. Don't use sledgehammer when screwdriver works.

2. "I want to be sure everything is fresh"

Fix: Docker layer caching is reliable. Only invalidates cache when files actually change.

3. "Someone told me to always use it"

Fix: That person was wrong. Share this guide with them.

4. "The docs/tutorial used it"

Fix: Many tutorials are poorly written. They use --no-cache to avoid caching issues in demos.

📂 Volume Mount Best Practices

Core Principle: Code lives on HOST, container reads via volume mount.

Basic Pattern

services:
  app:
    volumes:
      - ./app:/app  # Mount source code

Advanced: Selective Mounting

❌ Bad ✅ Good
volumes:
  - .:/app
(Mounts everything including .git, __pycache__) 		volumes:
  - ./app:/app/app
  - ./static:/app/static
  - /app/.venv # Exclude
  - /app/__pycache__ # Exclude

Excluding Directories

volumes:
  - ./app:/app
  - /app/.venv           # 👈 Exclude venv
  - /app/node_modules    # 👈 Exclude node_modules
  - /app/__pycache__     # 👈 Exclude cache

Why: Container dependencies differ from host (different OS, Python version, etc.)

Read-Only Mounts

volumes:
  - ./config:/app/config:ro   # Read-only
  - ./certs:/app/certs:ro      # Read-only

Named Volumes for Data

services:
  db:
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:  # Managed by Docker

⚡ BuildKit Cache Optimization

For when you DO need to rebuild: Make it fast with cache mounts

Enable BuildKit

# PowerShell
$env:DOCKER_BUILDKIT = "1"

# Or in docker-compose.yml
services:
  app:
    build:
      context: .
      cache_from:
        - myapp:latest

Cache Mount Pattern - Python

FROM python:3.11-slim

WORKDIR /app

# Cache pip downloads between builds
RUN --mount=type=cache,target=/root/.cache/pip \
    --mount=type=bind,source=requirements.txt,target=requirements.txt \
    pip install -r requirements.txt

COPY . .
Result: Only NEW or CHANGED packages are downloaded. Existing packages use cache.

Cache Mount Pattern - Node.js

FROM node:18-alpine

WORKDIR /app

# Cache npm packages between builds
RUN --mount=type=cache,target=/root/.npm \
    --mount=type=bind,source=package.json,target=package.json \
    --mount=type=bind,source=package-lock.json,target=package-lock.json \
    npm ci

COPY . .

Multi-Stage Build with Cache

# Stage 1: Dependencies (cached)
FROM python:3.11-slim as deps
WORKDIR /app
RUN --mount=type=cache,target=/root/.cache/pip \
    --mount=type=bind,source=requirements.txt,target=requirements.txt \
    pip install -r requirements.txt

# Stage 2: Development (uses deps cache)
FROM deps as dev
CMD ["uvicorn", "app:app", "--reload"]

# Stage 3: Production (uses deps cache)
FROM deps as prod
COPY . .
CMD ["uvicorn", "app:app", "--workers", "4"]

🔧 Troubleshooting

Changes Not Appearing?

# 1. Check volume mount
docker inspect mycontainer | grep Mounts

# 2. Check hot-reload enabled
docker logs mycontainer | grep reload

# 3. Restart container
docker compose restart app

# 4. Check file permissions (Linux/Mac)
docker compose exec app chown -R appuser:appuser /app

Port Already in Use?

# Windows
netstat -ano | findstr "8000"

# Linux/Mac
lsof -i :8000

# Change port in docker-compose.yml
ports:
  - "8001:8000"  # Different host port

Database Connection Fails (Native Dev)?

# Ensure DB container running
docker compose up -d db

# Check DB port
docker compose ps db

# Test connection
psql -h localhost -p 5433 -U user -d db

⛔ Anti-Patterns Summary

Top 5 Docker Development Mistakes

# Anti-Pattern Cost Fix
1 Using --no-cache for code changes 14.5 min per build Use regular build or hot-reload
2 No volume mounts 5 min per change Add volumes to docker-compose.yml
3 Forgetting --reload flag Manual restart needed Add --reload to command
4 Mounting everything (including .git) Slower, conflicts Selective mounts + .dockerignore
5 Wrong layer order in Dockerfile Invalidates cache Dependencies first, code last
