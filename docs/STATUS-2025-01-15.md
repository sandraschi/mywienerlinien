## Architecture Details

### Dual-Standard Design

The application successfully implements a **dual-standard architecture**:

1. **FastAPI Web Application** (`frontend/app.py`)
   - HTTP/WebSocket transport
   - Interactive web UI
   - Real-time vehicle tracking
   - Status dashboards

2. **FastMCP MCP Server** (`frontend/mcp_server/server.py`)
   - stdio transport (Claude Desktop)
   - AI assistant integration
   - Natural language queries
   - Tool-based interface

3. **Shared Backend**
   - `data_loader.py` - GTFS data loading
   - `database.py` - PostgreSQL database
   - `vehicle_service.py` - Real-time vehicle data
   - `disruption_alerts.py` - Service disruptions

### FastMCP 2.13 Compliance

- ✅ MCP Specification 2025-06-18 compliance
- ✅ Tool registration with type hints
- ✅ Pydantic models for validation
- ✅ Async/await support
- ✅ Error handling and logging
- ✅ Resource management
- ✅ Prompt support

### Data Flow

```
Wiener Linien API
    ↓
vehicle_service.py (caching, rate limiting)
    ↓
    ├──→ FastAPI Web App (HTTP/WebSocket)
    └──→ FastMCP Server (stdio/MCP protocol)
            ↓
        Claude Desktop / AI Assistants
```

## Usage

### Running the MCP Server

```bash
# Direct execution
python -m frontend.mcp_server.server

# With FastMCP CLI
fastmcp dev frontend.mcp_server.server:mcp
```

### Claude Desktop Configuration

Add to Claude Desktop configuration:
```json
{
  "mcpServers": {
    "vienna-transit": {
      "command": "python",
      "args": ["-m", "frontend.mcp_server.server"],
      "env": {
        "PYTHONPATH": "${PWD}",
        "PYTHONUNBUFFERED": "1"
      }
    }
  }
}
```

### Testing

```bash
# Install dependencies
pip install -e ".[dev]"

# Run tests
pytest tests/mcp_server/

# Run linting
ruff check frontend/mcp_server/

# Run type checking
mypy frontend/mcp_server/
```
